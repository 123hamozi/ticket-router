# Самоанализ решения (Self-Review)

## Самая слабая часть текущей архитектуры
В рамках реализованного Proof-of-Concept (PoC) самой слабой точкой является синхронная обработка всех запросов внутри единого пула воркеров FastAPI. Отсутствует полноценный асинхронный контур с брокером сообщений. При пиковой нагрузке (до 20 000 обращений за 10 минут) это неизбежно приведет к исчерпанию ресурсов (OOM) и отказам в обслуживании (HTTP 503). 

## Сделанные допущения
* Исторический датасет для обучения ML-модели консистентен и заранее очищен от мусорных данных.
* Клиентские приложения (веб-форма, мобильное приложение) реализуют стратегию повторных запросов (exponential backoff) при получении статуса HTTP 429 (Too Many Requests).
* Модель машинного обучения разворачивается локально в контейнере, без сетевых задержек на обращение к внешним API.

## Нерешенные риски
Основным алгоритмическим риском остается дрейф данных (Data Drift), когда изменение характера обращений (например, массовый сбой интеграции) приведет к снижению качества маршрутизации без явных технических сбоев системы.

## План улучшений
* Интеграция реального брокера сообщений (RabbitMQ) для изоляции асинхронного пути (Slow Path).
* Замена эвристического мока на обученную модель логистической регрессии с пайплайном векторизации.
* Развертывание реляционной базы данных (PostgreSQL) для персистентного хранения логов предсказаний.

## Требования для Production-запуска
* Внедрение MLOps-практик: версионирование данных и моделей (DVC/MLflow) для обеспечения воспроизводимости экспериментов.
* Настройка инфраструктурного мониторинга (Prometheus + Grafana) с алертами на превышение 99-го перцентиля задержки (Latency).
* Проведение полноценного нагрузочного тестирования.

## Границы автоматизации
Категорически не рекомендуется полностью автоматизировать тикеты, связанные с юридическими претензиями, угрозами безопасности и возвратом крупных денежных средств. Эти категории требуют обязательного этапа ручного подтверждения оператором.

## Критерии остановки пилота
Пилотный проект должен быть немедленно остановлен, если доля ложноположительных срабатываний (False Positives), приводящих к некорректной маршрутизации критических инцидентов, превысит 5%, или если в логах базы данных будет зафиксирована утечка невырезанных персональных данных (PII).

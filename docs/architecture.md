# Архитектура системы автоматизации обработки тикетов

## 1. Обзор целевой архитектуры (Target Architecture)

Система спроектирована с учетом жестких требований к высокой доступности (Highload) во время инцидентов (до 20 000 обращений за 10 минут) и строгих ограничений по работе с персональными данными (PII). 

Основной паттерн — **Fast & Slow Paths** (Быстрый и медленный пути) с использованием легковесного ML-классификатора в качестве шлюза первой линии.

### 1.1 Основные компоненты
*   **API Gateway & Load Balancer:** Балансировка входящего трафика от различных каналов (веб, мобильное приложение, email).
*   **Синхронный API-слой (FastAPI):** Точка входа для приема тикетов. Осуществляет первичную валидацию, маскирование PII и вызов легковесной модели.
*   **Модуль PII Scrubber:** Регулярные выражения (Regex) и легковесные NER-модели для поиска и маскирования номеров телефонов, email, паспортов и банковских карт.
*   **ML-классификатор (Tier 1):** TF-IDF векторизатор в связке с логистической регрессией (или легковесным градиентным бустингом). Обеспечивает задержку (latency) менее 50 мс на запрос.
*   **Message Broker (RabbitMQ / Kafka):** Очередь для асинхронной обработки тикетов, требующих ручного разбора или отложенной отправки. Сглаживает пиковые нагрузки.
*   **Хранилище (PostgreSQL):** Реляционная база данных для хранения метаданных тикетов, истории статусов и логирования работы модели (включая confidence score) для последующего дообучения.

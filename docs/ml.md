# Машинное обучение и алгоритмы обработки

## 1. Декомпозиция ML-задач
В рамках системы автоматизации обработки тикетов выделяются две ключевые алгоритмические задачи:
1. **Деидентификация (PII Scrubbing):** Извлечение и маскирование чувствительных данных. Решается строго детерминированными правилами (Regular Expressions) для обеспечения 100% контроля и недопущения утечек (Data Leakage) перед передачей текста в ML-модели.
2. **Многоклассовая классификация интента:** Определение категории обращения (например, `billing`, `technical_support`, `refund`) на основе очищенного текста.

## 2. Обоснование выбора ML-подхода
Для классификации выбран подход **TF-IDF + Logistic Regression**.

*   **Почему не LLM / RAG:** Использование LLM для каждой входящей заявки (до 20k в пиковые 10 минут) приведет к неприемлемо высокой латентности (секунды на запрос) и астрономическим затратам на инференс. Кроме того, сохраняется риск prompt injection и передачи остаточных PII во внешние API.
*   **Почему не тяжелые нейросети (Transformer/BERT):** Для задачи базовой маршрутизации текстов вычислительная сложность BERT избыточна. Логистическая регрессия обеспечивает время инференса < 50 мс на CPU.
*   **Преимущества регрессии:** Модель выдает хорошо откалиброванные вероятности (predict_proba), что критически важно для корректной работы порога уверенности (Confidence Score).

## 3. Базовые решения (Baselines)
Перед внедрением ML-модели запускаются следующие бейзлайны:
*   **Naive Baseline:** Предсказание самого частотного класса (Majority Class).
*   **Heuristic Baseline:** Классификация на основе словаря ключевых слов (например, наличие слова "оплата" -> `billing`).

## 4. Стратегия валидации и метрики
Поскольку поток тикетов неоднороден и присутствует сильный дисбаланс классов, валидация и оценка качества строятся следующим образом:

*   **Метрики:** Использование классической `Accuracy` исключено, так как она дает обманчиво высокие результаты на мажоритарном классе. Для оценки качества используются `PR-AUC` (Area Under the Precision-Recall Curve) и `F1-macro`, позволяющие оценить качество работы модели на редких инцидентах.
*   **Валидация:** Применяется `Stratified K-Fold` кросс-валидация для сохранения пропорций классов в обучающей и отложенной выборках. 
*   **Предотвращение утечки данных (Data Leakage):** Векторизатор (TF-IDF) обучается (`fit`) строго на тренировочной выборке внутри каждого фолда. На валидационной выборке применяется только трансформация (`transform`). 

## 5. Обработка низкой уверенности (Low Confidence)
Система использует концепцию порога уверенности (Confidence Threshold):
1.  Если вероятность предсказанного класса $P(y|X) \ge 0.85$, решение принимается автоматически.
2.  Если $P(y|X) < 0.85$, модель признает свою неуверенность. Тикет помечается флагом эскалации и маршрутизируется на ручной разбор (Human-in-the-loop).

## 6. Данные и разметка
Предполагается, что модель обучается на исторических данных системы (логи тикетов за прошедший год). Разметка извлекается автоматически из исторических статусов (куда тикет был в итоге переведен оператором). Перед обучением весь исторический датасет пропускается через скрипты дедупликации и PII Scrubber.
